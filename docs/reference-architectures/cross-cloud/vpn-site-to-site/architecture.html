Three-phase apply (because both sides have local Terraform state — manual outputs-as-inputs paste)

  • Phase 1 — Azure (Side A): apply VNet, GatewaySubnet, Public IP, VPN GW, NSG, NIC, VM. create_connection = false (LNG + Connection NOT created). Capture azure_gw_public_ip, azure_bgp_asn, azure_vnet_cidr. Slow: 30–45 min for VPN GW.
  • Phase 2 — AWS (Side B): paste Azure outputs into AWS tfvars. Apply VPC, subnets, IGW, VGW + attachment, CGW (with Azure IP), VPN Connection (BGP, tunnel1_inside_cidr pinned), workload RT + propagation, SG, IAM, EC2. Capture aws_tunnel1_address, aws_tunnel1_psk (sensitive).
  • Phase 3 — Azure (Side A round 2): paste AWS outputs into Azure tfvars, flip create_connection = true. Apply creates LNG (lng-aws-tunnel1) + Connection (cn-azure-aws). Tunnel comes up within 1–2 minutes; BGP exchanges prefixes shortly after.

Cross-cloud ping — SSH into Azure VM via Bastion / SSM into AWS EC2, then ping <other-side-private-ip>.

Teardown order (per-side destroy.sh via TF dependency graph)

Azure (10–25 min total): Connection → LNG → VPN GW (slow!) → Public IP → subnets → VNet → RG.
AWS (~5 min total): EC2 → SG → IAM role/profile → VPN Connection → CGW → VGW Attachment → VGW → route propagation → route tables → subnets → IGW → VPC.
Common hangs: Azure Public IP can't delete while VPN GW holds it (TF orders implicitly). AWS VGW detach hangs if VPN Connection or route propagation lingers (both managed). If Azure Connection destroy hangs, the AWS Connection is the likely cause.
Stranded-cost watch: AWS public IPv4s ($0.005/hr each since 2024); Azure public IPs (~$0.005/hr). Both intentionally absent on workload VMs.
End-to-end packet flow (Azure VM → AWS EC2)
  • 1. Azure VM ICMP → AWS EC2 private IP (10.20.1.x)
  • 2. Azure system route table: 10.20.0.0/16 → VPN GW (BGP-learned)
  • 3. VPN GW encrypts, IPSec to AWS tunnel 1 IP over internet
  • 4. AWS tunnel decrypts → VGW → route table sees 10.20.1.0/24 → local
  • 5. SG: ALLOW ICMP from 10.10.0.0/16 → reaches EC2
  • 6. EC2 responds; reverse path uses BGP-learned 10.10.0.0/16 → VGW
  • 7. Azure NSG: ALLOW ICMP from 10.20.0.0/16 → reaches VM

Gotchas (from cross-cloud + per-cloud ref docs)

  • GatewaySubnet name — must be exactly GatewaySubnet. Any other casing fails apply.
  • Public IP SKU — VpnGw1 needs Standard. Basic SKU PIP fails validation.
  • BGP requires Gen2 SKU — Basic SKU has no BGP.
  • PSK char set — AWS PSK must match [A-Za-z0-9._]{8,64}, no leading 0.
  • BGP ASN reservations — AWS rejects 7224, 9059, 17493, 22697…. Stay in private range 64512–65534.
  • Azure default ASN is 65515 — we picked 65010/65020 to avoid accidental clash.
  • Asymmetric tunnels — tunnel 2 stays DOWN; not an error.
  • Encryption domain — route-based both sides → 0/0 ↔ 0/0; routing decides actual flow.
  • MSS clamping — AWS enforces by default; if 1500-byte pings work but TCP stalls, suspect MSS.
  • Tunnel inside CIDR is force-new on AWS — changing it replaces VPN Connection, generates new tunnel public IPs.
  • Apply slowness — Azure VPN GW 30–45 min, AWS VPN Connection ~4 min.
  • Public IPv4 cost (AWS, since 2024) — every EIP, every default-assigned EC2 public IP, even attached, $0.005/hr.
  • IAM names need cross-cloud-labs- prefix — deployer policy only authorises IAM actions on ARNs matching that prefix.
  • Active-active needed for HA — using both AWS tunnels requires Azure VPN GW active_active = true, two PIPs, two LNG/Conn pairs. Out of scope v1.
  • AWS workload subnet has 0/0 to IGW — technically internet-attached so SSM works without VPC endpoints. SG ingress is the only protection.
  • Azure VM is private-only — reach via Bastion / in-VNet jump.
  • Tag actions are load-bearing — AWS provider default_tags tags resources at create time; missing iam:Tag* permissions fail the create silently-then-loudly.
  • CRLF in .env — Windows line endings break source ../../../.env; strip with sed -i 's/\r$//' or pipe through tr -d '\r'.
