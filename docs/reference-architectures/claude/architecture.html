Claude Code harness — main session
Reads CLAUDE.md + memory on every turn. Plans the task, decides which tool to call. Tool calls are intercepted by the harness, not run directly.
  • Reasons about user request
  • Decides: direct tool, subagent, or ask user
  • Routes Bash / Read / Edit / Write / Agent calls through permission checks
  • Receives subagent results into context
settings.json — permission policy
Static allow/ask/deny patterns for Bash/Read/Write tool inputs.
  • allow read-only TF, AWS describe-*, az show, git status/diff/log
  • ask tf apply/destroy, IAM/EC2 create-delete, gh pr merge
  • deny rm -rf /*, push origin main, Read(./.env)
  • env: TF_IN_AUTOMATION=1
  • Wires PreToolUse hook below
hooks/block-main-write.sh
PreToolUse Bash hook. Backstop for the bare-git push case the static deny pattern can't catch.
  • Reads tool input via jq
  • Skips non-git commands fast (~5ms)
  • If git commit/git push AND HEAD on main/master → exit 2 (block)
  • Fail-closed: missing jq → exit 1 (block)
allow → run
Read-only / reversible. No prompt.
ask → prompt user
State change. Awaits explicit approval.
deny → refused
No context where this is right. Hard block.
hook block → refused
Runtime state didn't pass (e.g., on main branch). Stderr shown to Claude.

Recurring workflows (“routines”) — how every change is expected to flow

Encoded across CLAUDE.md, settings.json, hooks, and reviewer subagents. Named here so they can be invoked explicitly.
1. Plan → confirm → apply
State plan. Wait for user OK. tf plan -out. Show. Apply only on go.
2. Phased cross-cloud apply
Side A (no peer info) → Side B (paste A outputs) → Side A round 2 (paste B outputs, flip create_connection).
3. Daily teardown
Per-lab destroy.sh or repo-root ./teardown-all.sh. End of every working day.
4. Branch + PR (never push to main)
Feature branch → commit → push → gh pr create. Backed by deny pattern + hook + repo-side pre-push hook.
5. Doc-as-source-of-truth
Every resource add/change ships with the matching docs/reference-architectures/<cloud>/ doc in the same PR.
6. Pre-merge review (multi-agent)
code-reviewer + terraform-reviewer always; security-reviewer when IAM/net/secrets/public touched. Run in parallel.
7. Cost-impact statement on PR
$/hr and $/month for any new billable resource. Dominant driver called out. Required by CLAUDE.md.
8. Ref-arch refresh after deploy
When deploy reveals code-vs-doc drift, doc gets the truth. Same branch or follow-up PR.
terraform apply / destroy
Local state. Sources .env for both clouds via set -a && source ../../../.env && set +a.
Reads AWS_* and ARM_* vars. Talks to both providers.
terraform-deployer (AWS IAM user)
Programmatic access only. PowerUserAccess + inline cross-cloud-labs-iam-scoped.

  • Tag actions are load-bearing (default_tags applies at create)
  • Self-Deny on its own user ARN (no escalation)
cross-cloud-labs-tf (Azure SP)
App Reg + SP, client-secret auth. Contributor at subscription scope.
  • No RBAC role mutation, no Entra changes
  • Secret rotates yearly; az ad app credential reset --append
  • Smoke test: az login --service-principal ...

Standing constraints

  • $100 AWS credit must last ~6 months
  • Azure tenant is real money (no credit)
  • Local TF state on both sides → manual outputs paste between sessions
  • Two parallel Claude sessions: AWS clone + Azure git worktree
  • Azure VPN GW: 30–45 min to provision, 10–20 min to destroy
  • Daily teardown is non-negotiable

What stops bad things

Push to main: deny pattern + hook + repo pre-push hook (3 layers)
Read .env: Read tool deny
Surprise apply: ask tier on tf apply/destroy
Forgotten resources: daily teardown routine + every-resource-needs-destroy rule
Doc drift: reviewer agents + ref-arch-canonical rule
